# Aphids and Ladybugs

This is a small Rust simulation of aphids and ladybugs moving around a two-dimensional board, sharing food, reproducing, starving, and fighting when predator and prey occupy the same cell.

The project uses `clap` for command-line parsing and `rand` for random number generation.

## Project Layout

The repository is organized around a CLI executable, a GUI executable, and three runtime configuration files:

```text
.
|-- Cargo.toml
|-- Cargo.lock
|-- README.md
|-- aphid.conf
|-- board.conf
|-- ladybug.conf
`-- src/
    |-- bin/
    |   `-- gui.rs
    |-- lib.rs
    `-- main.rs
```

`src/lib.rs` contains the simulation model, configuration loading/parsing, random number wrapper, simulation rules, and rule tests.

`src/main.rs` contains command-line parsing, board rendering, turn-summary printing, sleeping, and CLI tests.

`src/bin/gui.rs` contains the Macroquad visual simulation.

`board.conf` defines the board size and starting creature positions.

`aphid.conf` defines aphid probabilities.

`ladybug.conf` defines ladybug probabilities.

`target/` is generated by Cargo and ignored by Git.

## Dependencies

Runtime dependencies are intentionally small:

```text
clap   command-line parsing and help output
macroquad   realtime GUI visualization
rand   seeded and unseeded random number generation
```

## Build

Build the debug executable:

```sh
cargo build
```

Build an optimized release executable:

```sh
cargo build --release
```

## Run

Run with the default configuration files:

```sh
cargo run
```

Run a short deterministic simulation:

```sh
cargo run -- --turns 10 --delay-ms 0 --seed 42
```

Run the Macroquad GUI visualizer. It starts from fixed seed `42` by default:

```sh
cargo run --bin gui
```

The executable accepts these optional flags:

```text
--turns <number>     Maximum number of turns to simulate. Default: 60.
--delay-ms <number>  Delay between printed turns in milliseconds. Default: 400.
--seed <number>      Optional seed for reproducible random behavior.
-h, --help           Print help text.
-V, --version        Print the package version.
```

`clap` validates command-line arguments. Invalid flags, missing values, and invalid numeric values are reported as errors. The process exits with status code `2` after printing usage text.

## GUI Controls

The GUI uses the same `board.conf`, `aphid.conf`, and `ladybug.conf` files as the CLI.

```text
Space     pause or resume
N         advance one turn
R         reset to the selected seed and probabilities
Up/Down   adjust simulation speed
Esc       quit
```

The side panel also provides mouse controls for play, step, reset, speed, seed, and all aphid and ladybug probabilities. Changing a probability affects future turns immediately; reset restarts the run with the selected seed and probabilities. Creature movement is animated between turns, and a population history graph below the board tracks recent aphid and ladybug counts. Hover over a board cell to inspect its coordinates, food, aphids, and ladybugs.

## Board Configuration

`board.conf` is whitespace-delimited. It does not support comments or extra trailing values.

The format is:

```text
<rows> <columns>
<aphid-count>
<aphid-x> <aphid-y>
...
<ladybug-count>
<ladybug-x> <ladybug-y>
...
```

Example:

```text
10 10
5
3 5
4 8
2 9
1 6
1 9
4
5 9
1 1
3 8
9 2
```

Coordinates are zero-based. `x` is the row and `y` is the column.

Rows and columns must both be greater than zero. If `board.conf` is missing or invalid, the program loads built-in standard board data.

Creature positions outside the board are skipped with a warning.

Starting aphids have `10` life.

Starting ladybugs have `15` life.

Each board cell starts with a random food value from `0` through `9`.

## Aphid Configuration

`aphid.conf` is whitespace-delimited. It does not support comments or extra trailing values.

The format is:

```text
<move-probability>
<kill-probability>
<accomplice-probability>
<procreation-probability>
```

Default values:

```text
0.7
0.2
0.1
0.4
```

All values must be probabilities from `0.0` through `1.0`.

If `aphid.conf` is missing or invalid, the default aphid parameters are used.

## Ladybug Configuration

`ladybug.conf` is whitespace-delimited. It does not support comments or extra trailing values.

The format is:

```text
<move-probability>
<kill-probability>
<direction-change-probability>
<procreation-probability>
```

Default values:

```text
0.7
0.2
0.4
0.2
```

All values must be probabilities from `0.0` through `1.0`.

If `ladybug.conf` is missing or invalid, the default ladybug parameters are used.

## Board Output

The simulation prints the board at startup and after every turn.

Each cell is printed as two symbols:

```text
<aphid-count><ladybug-count>
```

Count symbols are:

```text
_   zero creatures
1-9 exact creature count
~   more than nine creatures
```

Examples:

```text
__   empty cell
1_   one aphid and no ladybugs
_1   no aphids and one ladybug
23   two aphids and three ladybugs
~1   more than nine aphids and one ladybug
```

After each completed turn, the simulation also prints a numeric summary:

```text
Turn: 1 | Aphids: 5 | Ladybugs: 4 | Births: 0 | Deaths: 0 | Food: 432
```

The summary reports living aphids, living ladybugs, births during that turn, deaths during that turn, and total remaining board food.

## Turn Order

Each turn starts by taking a snapshot of all creatures that existed at the beginning of the turn. Creatures born during the turn do not act until the next turn.

The simulation then runs these phases:

1. Movement for all original turn creatures.
2. Combat for all surviving original turn creatures.
3. Removal of creatures killed in combat.
4. Procreation for all surviving original turn creatures.
5. Starvation for all surviving original turn creatures.
6. Removal of creatures killed by starvation.

Within each phase, creatures are processed in creation order.

The simulation stops when either all creatures are extinct or the configured turn limit is reached.

## Movement Rules

Aphids may move once per turn. If movement succeeds, an aphid chooses one of the eight surrounding directions at random.

Ladybugs may change their preferred direction set once per turn. A preferred direction set contains three adjacent directions, such as northwest, north, and northeast. If movement succeeds, a ladybug chooses one of its three preferred directions at random.

When a creature attempts to move outside the board, it bounces back into the board instead of wrapping around. On a one-row or one-column board, the bounced coordinate is clamped to the only valid coordinate.

## Combat Rules

Combat can happen when aphids and ladybugs occupy the same cell.

An aphid can kill one ladybug in its cell. Its kill probability is:

```text
aphid kill probability + other aphids in the same cell * aphid accomplice probability
```

The acting aphid does not count as its own accomplice. The final probability is capped at `1.0`.

A ladybug can kill one aphid in its cell using the configured ladybug kill probability.

Killed creatures are removed after the combat phase and cannot procreate or starve later in the same turn.

## Procreation Rules

Aphids can procreate when more than one aphid occupies the same cell. A new aphid is created in that cell with `2` life.

Ladybugs can procreate when more than one ladybug occupies the same cell. A new ladybug is created in that cell with `5` life and a random preferred direction set.

New creatures do not move, fight, procreate, or starve until the next turn.

## Starvation Rules

During starvation, each surviving original turn creature consumes from the food value of its current cell.

The cell food value is reduced by `1` before the creature checks whether food remains.

If the cell still has food after the reduction, the creature gains `1` life and then loses `1` life for the turn, leaving its life unchanged.

If the cell has no food after the reduction, the creature loses `1` life.

Food values can become negative.

A creature dies when its life drops below `1`.

## Randomness

The simulation uses `rand::rngs::StdRng` through a small wrapper in `src/lib.rs`.

Without `--seed`, the generator is seeded from operating system randomness.

With `--seed`, the same starting configuration and seed produce the same sequence of random decisions.

Example:

```sh
cargo run -- --turns 20 --delay-ms 0 --seed 12345
```
